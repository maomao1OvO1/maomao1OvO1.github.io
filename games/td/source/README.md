## 这是什么

一个安卓单机塔防游戏《共鸣之塔》的**完整源码**。玩法核心是原创的「元素共鸣」：
相邻摆放不同元素的塔会触发组合技（合计 91 种），同元素相邻则是「共振」。

- 纯 **HTML5 + Canvas 单文件**实现（HTML / CSS / JS 全在 `game.html` 里），无框架、无依赖、无构建步骤
- 安卓壳只是 WebView 容器，真正的游戏就是这一个文件
- 无联网、无内购、无广告、无统计埋点

## 拿到源码怎么玩

### 方式一：直接用浏览器跑（推荐，零门槛）
`game.html` 是标准的 HTML5 文件 —— **双击用浏览器打开就能玩**，也能直接改。
改完刷新页面即见效，不需要编译、不需要安卓工具链。

> 建议用 Chrome，按 F12 打开控制台 —— 报错会直接显示，改起来快得多。

### 方式二：装成安卓 APK
见 `../docs/modding.md` 里「想打包成自己的 APK」一节（需要 aapt2 / javac / d8 / apksigner）。
打包出来的包用**你自己的签名**即可，不需要和任何人一致。

### 方式三：直接改网上那个 APK
把 APK 后缀改成 `.zip` 解开，`assets/index.html` 就是源码（v8.20 起已移除全部加固，包内就是明文）。

## 数据都在哪（改游戏从这里下手）

游戏是**数据驱动**的，几乎所有内容都集中在几个对象字面量里，搜关键字就能定位：

| 想改什么 | 搜索 |
|---|---|
| 9 座塔（造价 / 伤害 / 攻速 / 射程 / 特性 / 专属成长） | `var ELEMS = {` |
| 敌人（血量 / 速度 / 金币 / 特性） | `var ENEMIES = {` |
| 15 个关卡（波数 / 初始金币 / 难度 / 路径） | `var LEVELS = [` |
| 76 张强化卡 | `var BUFF_POOL = [` |
| 6 种天气 | `var WEATHERS = {` |
| 4 个主动技能 | `var SKILLS = [` |
| 8 个元素套装 | `var ELEM_SETS = {` |
| 6 种敌人词缀 | `var ENEMY_AFFIXES = [` |
| 14 个成就 | `var ACHIEVEMENTS = [` |

> **加一座塔只需要加一条数据** —— 建塔面板、图鉴、升级面板都是遍历 `ELEMS` 生成的，会自动收录。
> 第 9 座塔「🔫 机枪」就是这么加的，可以当模板看。

完整的改造教程（含 8 个照着抄的例子）见 **[../docs/modding.md](../docs/modding.md)**。

## 跑测试（改完建议跑一遍）

仓库自带 **44 套自动化测试**，用 Node 跑，不需要浏览器 —— 它把游戏代码抽出来塞进一个假 DOM 里模拟运行：

```bash
node test/deep4.js game.html          # 单跑一套（deep4 = 完整通关）
for t in test/deep*.js test/audit_fuzz.js; do node "$t" game.html | tail -1; done   # 跑全套
```

其中 `test/audit_fuzz.js` 值得单独说：它会做**静态体检**（僵尸字段、词缀与套装是否真接入、
HTML 重复 id、引用不存在的元素）＋ **4000 次随机操作 fuzz**（随机建塔/开面板/乱点按钮/放技能/切美术/结算/跑帧），
并持续校验状态一致性与数值越界。改完之后跑它很容易发现自己漏了什么。

## 目录结构

```
source/
├── game.html              整个游戏（单文件，约 370KB）
├── test/                  44 套自动化测试（Node 跑，含 fuzz 审计）
├── patches/               开发过程存档（p_v*.py 按序可重放，能看到每一个版本改了什么）
└── README.md              本文件
```

> `patches/` 是**开发历史的活化石**：每一个版本改了什么、为什么改、踩了什么坑，都在里面。
> 想学「一个游戏是怎么从零长到 9 座塔、15 关、91 种共鸣的」，这条路比直接读成品源码清楚得多。
